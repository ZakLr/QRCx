## PHASE 2 — THE KEY EXPERIMENT: DOES THE RESERVOIR ADD INFORMATION? (4 hours)
### This is the highest-value work in the entire sprint. Do it on EXISTING pilot features
### while the full drive runs; repeat on full features in Phase 5.

**Scientific framing.** The current headline is "plain Ridge on the flattened raw window beats
every reservoir." But that comparison asks the wrong question. Table 3 already establishes that
the reservoir produces real, dissipation-driven signal (γ₁=0 → ~0% skill at every horizon;
γ₁=0.03 → +14.39% at h=12, DM p≈0). The unanswered question is whether that signal is
*redundant* with a linear map of the raw window, or *complementary* to it.

**Experiment — concatenated readout, four design matrices:**
- **A** = flattened raw 24×13 window (312 features)  [the current champion]
- **B** = v5 reservoir features (V×234)
- **C** = [A ⊕ B]  — quantum increment
- **C'** = [A ⊕ ESN features], ESN sized to match B's dimension  — **classical control, mandatory**

**Protocol:**
1. Ridge readout on each, alpha selected on the validation split only (never test).
2. Standardize each block before concatenation; report the alpha chosen per design matrix.
3. Primary test: **DM test of C vs A** on squared errors, per horizon h ∈ {1,3,6,12,24},
   HAC-corrected, plus moving-block bootstrap CI on the skill difference.
4. Fairness test: **DM of C' vs A** with the identical protocol. Report both side by side.
5. Also report B alone (already have it) so the reader sees all four.

**Interpretation rules (write the conclusion the data supports, not the one you want):**
- C > A significantly, and the C−A gain exceeds the C'−A gain → **headline becomes:
  "the quantum reservoir contributes forecast-relevant information not linearly present in the
  observation history, beyond what a dimension-matched classical reservoir contributes."**
  This is the paper's lead result.
- C > A significantly but C' ≥ C → honest framing: reservoir features add information, but
  quantum offers no advantage over classical reservoir features. Still a stronger, more
  informative result than the current draft.
- C ≈ A (no significant gain) → the current negative headline stands, now with a much sharper
  statement: the reservoir's signal is redundant with linear history. Report it cleanly.

**Supporting diagnostics (30 min each, both are paper figures):**
6. **Effective rank / spectrum of B.** SVD the reservoir feature matrix; report effective rank
   (e.g. participation ratio, or #components for 99% variance) vs γ₁. If 234 features have
   effective rank ~20, that quantitatively explains underperformance — a real mechanistic
   finding, not an excuse.
7. **Feature variance vs γ₁.** Show that at γ₁=0 the features are near-constant/frozen
   (no fading memory), which is the *mechanism* behind Table 3's collapse. This turns the
   ablation from "an effect exists" into "here is why."

**Deliverable:** `results/hybrid_readout.json` with DM p-values and CIs for A/B/C/C' at every
horizon; two diagnostic figures; a written 1-paragraph conclusion stating which interpretation
rule fired.

## PHASE 3 — DIRAC-3 ATTEMPT (runs alongside Phase 2; 4-hour box)

**Why:** "Phase 3 requires working implementations run on QCi's Dirac-3 via qBraid." The current
draft says "pending organizer clarification," which reads as unattempted. A genuine attempt —
even a failed one with the blocker documented — scores materially better.

**Formulation (legitimate, not a hack):** Dirac-3 solves polynomial optimization over
sum-constrained continuous/integer variables. Give it best-subset selection of the reservoir
readout features:

  minimize over z:  E(z) = −2·cᵀz + zᵀQz,  subject to Σz = K
  where c = feature–target covariances (train split), Q = feature Gram matrix (train split),
  z = selection variables. Quadratic — well within Dirac-3's stated 5th-order capability.

Pipeline framing for the write-up: **Stage 1** quantum reservoir (GPU density-matrix / CUDA-Q
trajectory) → **Stage 2** readout sparsification on Dirac-3 → **Stage 3** classical ridge on the
selected features.

**Tasks:**
1. `QRCx/readout/dirac3_selector.py`: build/submit/poll/decode via `qci-client`, sum-constraint
   handling, retries, result caching to `results/dirac3/`.
2. Local **simulated-annealing stand-in** behind the identical interface (`solver="sa"`) so
   development and CI never block on device access.
3. Run at K ∈ {32, 64, 128} on the frozen feature set. Compare against **Lasso** and **greedy
   forward selection** at equal K — Dirac-3 must be benchmarked, not merely used.
4. Record actual device parameters used (num_samples, relaxation schedule, allocation seconds)
   — the rubric demands concrete numbers.
5. **Fallback if device access fails:** run the SA stand-in for the full RMSE-vs-K comparison,
   and write an explicit paragraph: what was attempted, the exact error/blocker, the
   formulation that is ready to execute, and the SA results demonstrating the stage works
   end-to-end. Do not write "pending."
